# Архитектура Cogniva

Три связанные системы:

| Система | Задача | Где в коде |
|---|---|---|
| A. Student Intelligence Profile | Кто ученик и что он знает | `backend/app/{students,academics,learning,database}` |
| B. Adaptive 3D Engine | Интерактивные сцены из шаблонов + объектов + компонентов | `backend/app/{physics,scenes}`, `frontend/src/scenes` |
| C. Adaptive AI Tutor | Решает, КАК учить | `backend/app/{ai,diagnostics}` |

## Ключевые правила
1. **Оценка в школе ≠ освоение понятия.** Таблицы `GradeRecord` и `SubtopicProgress` разные.
2. **Числа считает код, не ИИ.** Физика — `backend/app/physics`, зеркало на TypeScript для ползунков.
3. **ИИ возвращает только JSON** (план сцены). Он проверяется схемой и валидатором; код от ИИ никогда не выполняется.
4. **Внешний вид ≠ математика.** Смена шара на вагонетку меняет только «оболочку» объекта.
5. **API-ключ только на сервере**; нет ключа → демо-режим.

## Поток данных
Профиль → выбор темы → диагностика (детерминированная проверка) → обновление mastery →
ИИ-план урока (стратегия + JSON сцены) → валидатор → физический калькулятор → сцена →
итоговый тест → обновление профиля.
